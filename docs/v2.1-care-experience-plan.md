# 心情日记 V2.1｜主动关怀体验重构计划书

> 本文件按产品负责人提供的原文整理归档，作为 V2.1 阶段的指导性规划文档。
> 文末附"实施状态对照"，标注每一项在 V2.0（当前已上线版本）里的完成情况。

## 1. 本轮迭代目标

**核心问题**

当前产品已经能够回答："用户今天是什么心情？"
但还没有很好回答："用户告诉我他不好之后，产品应该做什么？"

本轮不继续增加更多呼吸、音乐、冥想等内容，而是重构负面情绪后的核心体验。

**V2.1 核心目标**

将现有：记录情绪 → 补充信息 → 用户自己寻找关怀
升级为：表达情绪 → 产品回应 → 识别需要 → 主动行动 → 效果反馈 → 形成记忆

核心产品原则：**用户状态越差，产品要求用户做的事情越少。**

## 2. 用户反馈归纳

1. 表达负面情绪后，产品反馈不够明显
2. 产品不知道用户此刻到底需要什么（同样是"低落"可能对应完全不同的需求）
3. 关怀工具很多，但决策成本过高
4. 产品缺乏连续记忆（连续三天低落，每天仍从零开始）
5. 干预反馈（好一点/差不多/更糟）没有充分反哺下一次推荐

## 3. 本轮核心方案：Adaptive Care Flow

根据当前情绪、当前状态、用户需要、关联因素、历史有效方案，动态决定下一步交互。
不再是"不同情绪 → 推荐不同内容"，而是"不同状态 → 产品采用不同交互复杂度"。

## 4. 第一阶段：立即回应

用户选择「低落」，花园轻微淡化，弹出 Care Sheet：

> 今天好像有点难熬。不急着马上好起来。现在你更希望我怎么陪你？

四个入口：
- 陪我缓一下 —— 直接进入低负担关怀
- 我想说说 —— 允许用户表达发生了什么
- 帮我做点什么 —— 系统直接给一个最小行动
- 我现在什么都不想做 —— 接受用户拒绝

## 5. 「很糟」进入 Focus Care Mode

"很糟"不是"低落"的加强版，而是独立的 Focus Care Mode：主动隐藏连续记录、累计数据、洞察、普通推荐、多余导航、复杂标签，页面只保留：

> 好。今天先不用解释发生了什么。我们先让这一刻容易一点。

三个入口：陪我待一分钟 / 我想说出来 / 我想找个人，以及"我现在什么都不想做"。

## 6. 第二阶段：先问「现在是什么状态」

不立即问原因，先问"现在更像哪一种？"：脑子很乱 / 没有力气 / 特别烦 / 想哭 / 有点慌 / 什么都感觉不到 / 说不上来。

这层解决："用户现在需要什么类型的帮助？"

## 7. 第三阶段：再询问「可能和什么有关」

一级分类控制在 6 个以内：工作/学业、和人的关系、身体/睡眠、钱、一个人待着、说不上来。必要时展开二级标签（如"和人的关系"→家庭/朋友/伴侣/同事/其他）。

## 8. State × Context 关怀矩阵

同样的"工作问题"，不同状态不应给同一个建议。示例：

- **工作 × 脑子很乱** → Brain Dump（不用整理，把脑子里的事情都扔出来 → 系统帮忙分成"今天必须处理/可以之后再想" → 只做一个最小动作）
- **工作 × 没有力气** → 不做任务拆解，直接"离开屏幕 2 分钟"
- **人际关系 × 特别烦** → "陪我离开一下"
- **人际关系 × 想哭** → 不分析对错，"我想写下来"
- **睡眠 × 没有力气** → 不推荐运动，"陪我安静 2 分钟"
- **说不上来 × 低落** → "陪我缓一下"

## 9. 第四阶段：Micro Action Engine

状态越差、行动越小：很好 5–20 分钟 / 不错 3–10 分钟 / 一般 2–5 分钟 / 低落 1–3 分钟 / 很糟 30 秒–1 分钟。

首批 8 个 Micro Action：三次慢呼吸、放松肩膀、喝两口水、离开屏幕、Brain Dump、只决定下一步、给一个信任的人发一句话、什么都不做。核心：用户不需要选工具，系统直接给第一步。

## 10. Zero-navigation Intervention

Micro Action 不跳转"关怀"页面，在当前 Care Sheet 内完成，全程不离开花园（例："陪我缓一下"的 0–10s/10–30s/30–50s/50–60s 分段呼吸引导 + 完成后的效果反馈）。

## 11. Respect the Refusal

用户选择"我现在什么都不想做"后停止推荐、减少按钮：

> 好。那今天先不用做什么。你愿意把现在的感受留在这里，已经足够了。花园会替你留住今天。

只留"回到花园"，可选"放一点雨声"。产品必须允许用户拒绝被帮助。

## 12. 第五阶段：Care Memory

每次干预后保存 Mood / State / Context / Action / Result。下一次遇到类似状态（如"低落+脑子很乱+工作"），如果历史上 Brain Dump 比呼吸更常带来"好一点"，则提示：

> 上次遇到类似状态时，把脑子里的事情写出来，好像对你有一点帮助。今天还想试试吗？

系统只表达"过去似乎有帮助"，不表达"这个方法对你有效"（避免过度归因）。

## 13. 第六阶段：连续情绪识别

连续多日低落/很糟后再打开产品，首页不从零开始，而是："又见面了。最近几天你好像都不太轻松。今天不用重新从头说。" 提供：还是前几天那件事 / 今天发生了新的事情 / 我也说不上来。

## 14. Delayed Check-in

对中高强度负面情绪，用户再次打开产品时轻量回访（例："下午工作上的事情让你有点烦，现在怎么样了？"），四个分支：已经过去一点了 / 还是会想到（追问"想继续处理，还是今天先放下？"）/ 更难受了（降低行动负担，不重复原方案）/ 不想聊这个。

## 15–16. AI 接入位置与输出限制

Rule Engine 决定：处于哪种 Care Mode、是否减少 UI、允许推荐哪些行动、是否进入安全支持路径、历史行为统计、Care Memory 排序。

LLM 只负责：① 理解自由文本（识别可能相关的因素）② 生成自然回应（非模板拼接）③ Brain Dump 整理（拆成必须处理/可以以后/暂时不用）④ 将 Mood+State+Context+History 组合成 2–3 句自然语言。

输出限制：每次最多 2–3 句话；禁止长篇心理分析、诊断、贴标签、强行积极、"你应该"句式、自动推断因果、一次给 5 个建议。标准结构：回应当前状态 → 降低压力 → 一个下一步。

## 17. 安全层

"很糟"不自动判断安全风险；但自由文本中出现明确的即时伤害风险表达时，停止普通推荐流程，进入独立 Safety Flow（不用呼吸/音乐/种花替代现实支持），提供：联系可信任的人、寻求当地紧急支持、专业支持入口、保持当前安全的低负担下一步。Safety Layer 独立于 LLM 推荐系统。

## 18. 页面交互改造

很好/不错：种花反馈 → 积极体验强化 → 可选"给未来的自己留句话"。
一般：正常记录 → 可选补充。
低落：Care Sheet 自动出现 →"你现在需要什么？"
很糟：Focus Care Mode。

## 19. 本轮不做什么

更多呼吸类型、更多音乐、更多冥想、AI 聊天机器人、社区、大量植物图鉴、更多统计图、复杂成就系统。原因：当前核心问题不是内容不足，而是已有能力没有形成顺畅的主动关怀体验。

## 20. MVP 开发优先级

**P0**：① 低落/很糟主动 Care Sheet ② "你现在需要什么？"四条分支 ③ 当前状态选择（7 种）④ Micro Action（呼吸/Brain Dump/喝水/离屏/下一步/不行动）⑤ 干预反馈

**P1**：⑥ Care Memory ⑦ 历史推荐 ⑧ 连续低落识别 ⑨ Delayed Check-in

**P2**：⑩ AI 理解自由文本 ⑪ AI 个性化回应 ⑫ AI Brain Dump ⑬ AI 综合多因素生成行动建议

## 21–22. 核心指标与漏斗

一级指标：Care Activation Rate（进入主动关怀流程的比例）、Care Action Start Rate（开始一个 Micro Action 的比例）、Care Completion Rate（完成行动的比例）、Subjective Relief Rate（反馈"好一点"的比例，非医学治疗效果指标）。长期指标：使用 Care Flow 的用户 D7 再记录率对比。核心漏斗：负面情绪记录 → Care Sheet 展示 → 选择需求 → 接受行动 → 完成行动 → 效果反馈 → 未来再次接受个性化关怀，重点定位用户在哪一步退出。

## 23. 本轮成功标准

不看"新增了多少功能"，而看用户点击"低落"之后 10 秒内能否获得：① 一次明确回应 ② 一个符合当前需求的选择 ③ 一个足够小的行动。三件成立即达标。

## 24. 产品长期演进

V2.1 完成后 → V2.2 Living Garden（我为什么想回来）→ V2.3 情绪说明书（持续记录为什么有价值）→ V2.4 Care Memory + AI（为什么用得越久越难替代）。

## 25. 本轮产品定位升级

当前："记录情绪，并获得自我关怀建议。"
V2.1："当你愿意告诉我今天不太好的时候，我不会只把它记录下来。"
核心体验原则：**先接住，再理解，最后才行动。**
